# Воспроизводимый запуск

## Настройка

Скопируйте `.env.example` в `.env`, укажите путь к набору данных и при
необходимости измените `DATABASE_URL`, лимит `DUCKDB_MEMORY_LIMIT`, число
потоков `DUCKDB_THREADS` и временный каталог `DUCKDB_TEMP_DIRECTORY`.
`make setup` устанавливает зависимости через uv, запускает PostgreSQL 16 с
постоянным именованным volume и применяет Alembic-миграции. Секреты `.env` не
коммитятся; Compose публикует порт только на localhost.

## Команды

| Команда | Действие |
|---|---|
| `make setup` | Установка зависимостей, запуск PostgreSQL и миграции |
| `make profile` | Профиль и проверки CSV в DuckDB |
| `make ingest` | Полный идемпотентный импорт |
| `make ingest FORCE=1` | Явная транзакционная пересборка |
| `make validate` | Проверки загруженной PostgreSQL-модели |
| `make marts` | Пересборка SQL-витрин в одной транзакции |
| `make analyze` | Проверка H1–H3, bootstrap-оценки и кластеризация на свежих витринах |
| `make validate-analytics` | Проверка fingerprint, целостности, наличия и свежести результатов |
| `make dashboard` | Запуск Streamlit-приложения без пересчёта аналитики |
| `make lint` | Ruff lint и форматирование |
| `make test` | Unit- и доступные интеграционные тесты |
| `make check` | Ruff и pytest |
| `make db-down` | Остановить контейнер PostgreSQL без удаления volume |

Для отдельного пути можно выполнить `uv run instacart profile --dataset путь`
или `uv run instacart ingest --dataset путь --force`. В качестве пути принимается
каталог CSV или ZIP. Профиль и итоговые проверки записываются в JSON; пути
настраиваются переменными `PROFILE_REPORT` и `VALIDATION_REPORT`.

Полный набор эталонных строк проверяется отдельно от общих инвариантов, поэтому
те же команды работают с небольшими тестовыми CSV. Для integration-тестов задайте
`INTEGRATION_DATABASE_URL` на пустую отдельную базу PostgreSQL. Тесты применяют
миграцию и проверяют импорт, повторный запуск, откат сбойной пересборки и
сохранность прежнего набора.

## Аналитический расчёт

После успешного импорта выполните `make marts`, затем `make analyze`. Аналитика
не запускает повторный импорт исходных файлов. Команда `analyze` останавливается
с понятной ошибкой, если витрины отсутствуют или fingerprint не совпадает с
активным импортом. После обновления активного импорта старые версии `mart` скрыты
представлениями, пока новые расчёты не зафиксированы.

`make analyze` принимает параметры `ANALYTICS_RANDOM_SEED` (по умолчанию 2026),
`BOOTSTRAP_REPLICATES` (200) и `SILHOUETTE_SAMPLE_SIZE` (5 000). Bootstrap
выполняется по всем покупателям активного импорта; в память за один шаг
загружается один вектор весов, а подготовленные H1/H2 агрегаты хранятся
разреженно. Переменные `ANALYTICS_REPORT` и
`ANALYTICS_MARKDOWN_REPORT` задают локальные отчёты JSON и Markdown. Они
располагаются в исключённом из Git каталоге `reports/`. Журнал запусков и
сводные результаты также доступны через `ops.analytics_runs` и витрины PostgreSQL.

`make validate-analytics` завершится ошибкой, если импорт отсутствует, витрины не
построены, результаты устарели или автоматические проверки согласованности не
пройдены. Актуальность проверяется по цепочке `active ingestion_run_id +
fingerprint → marts_run_id → analysis_run_id`. Успешная пересборка витрин
требует нового `make analyze`, даже если fingerprint не менялся. Представление
`ops.analytics_readiness` содержит состояния витрин, анализа и итоговый
`dashboard_ready`; публичные представления `mart` скрывают несовпадающие версии.

## Дашборд

После полного цикла `make setup → make ingest → make marts → make analyze →
make validate-analytics → make dashboard` приложение доступно на
`http://localhost:8501`. Для контейнерного запуска выполните
`docker compose --profile dashboard up --build dashboard`; приложение подключится
к `postgres` по внутреннему адресу Compose. Запуск Streamlit не перестраивает БД
или аналитику. Если `dashboard_ready` выключен, приложение показывает состояние
публикации и не отображает несогласованные результаты.
Для существующей установки сначала выполните `make migrate`: миграция создаёт
покрывающий индекс для обзорных агрегатов без перестроения данных витрин.

Локальная команда `make dashboard` слушает только `127.0.0.1`; Compose-приложение
слушает `0.0.0.0` внутри контейнера и публикует порт только на локальном адресе.
Подключение ограничено пятью секундами, отдельный запрос — 30 секундами. Пределы
можно задать через `DASHBOARD_CONNECT_TIMEOUT_SECONDS` и
`DASHBOARD_STATEMENT_TIMEOUT_MS`.

«Обзор данных» содержит KPI и активность по кодам `order_dow` и часам,
распределения размера корзины и дней между заказами. Часовые графики учитывают
все заказы, в том числе test; корзинные графики используют известный состав
prior/train. «Категории и товары» сравнивает объём позиций и доли повторов,
показывает отдельный график Top-N и ищет по всей выбранной выборке товаров;
время и размер корзины применяются только к `mart.category_activity`.
«Проверка гипотез» отображает опубликованные H1–H3, фактические границы
интервалов и отдельную описательную зависимость доли повторов от позиции товара.
Интерактивные срезы не пересчитывают статистики. «Сегментация покупателей»
показывает опубликованные размеры, средние признаки в исходных единицах, метрики
k и детерминированную PCA-выборку не более 12 000 точек с каждым сегментом.

Фильтры применяются только там, где витрина поддерживает соответствующую
гранулярность. `customer_count` неаддитивен по пересекающимся категориям; доли
повторных покупок рассчитываются отношением суммарного числителя к знаменателю.
Числовые коды дней недели не переименовываются в календарные дни. Категорийные
интервалы Wilson для H3 описательные; основные парные интервалы рассчитаны
bootstrap по покупателям. Данные наблюдательные и не обосновывают причинный
эффект.
