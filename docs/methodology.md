# Методология аналитики

## Источники и актуальность

Расчёты используют только активный импорт, указанный в `ops.active_dataset`.
Строки `core.order_items` не копируются целиком в Python: группировки по заказам,
товарам, категориям и позициям выполняет PostgreSQL. В Python передаются матрицы
частот и агрегированные признаки покупателей.

Результат каждого запуска записывается в `ops.analytics_runs`: fingerprint,
идентификатор импорта, тип и время запуска, параметры, статус, результаты и
проверки. Публикация витрин и результатов анализа выполняется одной транзакцией
под той же advisory-блокировкой, что и загрузка. Ошибка пересчёта откатывает новые
строки и сохраняет предыдущую публикацию. Представления схемы `mart` показывают
только версии, чей fingerprint совпадает с текущим `ops.active_dataset`; после
смены импорта устаревшие строки остаются скрытыми до успешного пересчёта.

## H1. День недели и час заказа

**H0:** распределение заказов по часам одинаково для всех значений `order_dow`.

**H1:** распределение заказов по часам зависит от `order_dow`.

Включаются все заказы, в том числе `test`. PostgreSQL формирует таблицу частот
7 × 24. Критерий независимости Пирсона χ² сравнивает наблюдаемые частоты с
ожидаемыми при независимости. Сохраняются матрицы наблюдаемых и ожидаемых частот,
распределения часов внутри каждой строки и остатки Пирсона. Размер эффекта —
Cramér’s V. Значения `order_dow` используются только как коды 0–6: они не
переименовываются в названия календарных дней.

Устойчивость V и доля bootstrap-выборок, в которых χ² остаётся значимым,
оцениваются ресемплированием покупателей. Выборка покупателей детерминирована
через `hashtextextended(user_id, seed)`.

## H2. Категория и повторная покупка

**H0:** доля повторно заказанных позиций одинакова между товарными категориями.

**H1:** хотя бы между некоторыми категориями доли различаются.

Используются только позиции заказов `prior` и `train`. Основной уровень
детализации — `aisles`; результаты отдельно рассчитываются и для `departments`.
Для каждого уровня строится таблица «категория × повтор/не повтор», применяется
χ² независимости и рассчитывается Cramér’s V. На уровне категорий сохраняются
числитель, знаменатель, доля и доверительный интервал. Интервалы получают
кластерным bootstrap по покупателям; если категория не попала в bootstrap-выборки,
для неё сохраняется интервал Wilson по полным числителю и знаменателю. Два
глобальных теста уровней категорий сопровождаются поправкой Holm.

## H3. Позиция товара в корзине

**H0:** вероятность повторной покупки одинакова для позиций 1, 10 и 20 в одном
заказе.

**H1:** хотя бы для одной пары этих позиций вероятности различаются.

Сравнение ограничено заказами `prior` и `train`, в которых известны как минимум
20 позиций. Тест Кокрана Q проверяет три связанных бинарных результата в одном
заказе. Для пар 1–10, 1–20 и 10–20 выполняются тесты Мак-Немара с поправкой Holm.
Сохраняются доли, знаковые разности в процентных пунктах, discordant-пары и
95%-е bootstrap-интервалы по покупателям. Дополнительно выполняется анализ пар,
где обе сравниваемые позиции относятся к одному `department`; он показывает,
сохраняется ли различие при совпадающем подразделении товара. Витрина
`mart.cart_position_stats` предоставляет детализацию по точному размеру корзины,
`eval_set`, `departments` и `aisles`.

Для совместной фильтрации категории по времени, `eval_set` и размеру корзины
предназначена агрегированная витрина `mart.category_activity`. Она хранит
числитель и знаменатель на уровне department и aisle, не копируя товарные
позиции из `core`.

## Общая статистическая интерпретация

Уровень значимости равен 0,05. Для χ² сохраняются ожидаемые частоты и
стандартизованные остатки Пирсона; Cramér’s V рассчитан как
`sqrt(χ² / (N × min(r − 1, c − 1)))`. Для парных проверок используется
непрерывная поправка Мак-Немара. Поправка Holm применяется к нескольким парным
проверкам H3 и к двум уровням категорий H2.

Для p-value ниже диапазона float JSON сохраняет ноль в числовом поле и
дополнительный `log10_p_value`; Markdown показывает `<1e-300`, а не трактует
машинный underflow как точную нулевую вероятность.

Обычные тесты рассматривают таблицу частот как базовую модель. Для проверки
чувствительности добавлена кластерная повторная выборка покупателей: 10 000
покупателей (или вся доступная совокупность, если она меньше), 200 повторов,
фиксированный seed 2026. Для H1 и H2 сохраняется доля повторов с `p < 0,05`; для
H3 — bootstrap-интервалы разности долей. Сегментные доли и описательные числа
нельзя считать причинным эффектом. Низкий p-value при большом объёме данных сам
по себе не означает большой практический эффект.

## Кластеризация покупателей

Признаки рассчитываются только по историческим заказам `prior`:
число заказов, средний размер корзины, доля повторов, средний интервал между
заказами, число уникальных товаров, aisles и departments. Интервал для первого
заказа отсутствует; отсутствующие значения замещаются медианой признака.
Значение интервала ограничено источником сверху 30 днями.

Для асимметричных неотрицательных признаков применяется `log1p`; доля повторов
остаётся в исходной шкале. Затем применяется `StandardScaler`. K-Means обучается
для k от 2 до 8, десять инициализаций на каждом k, фиксированный seed. Inertia
считается на всех подходящих покупателях; silhouette — на детерминированной
выборке максимум 5 000 покупателей. Выбирается максимальный silhouette среди k,
у которых каждый кластер содержит не менее `max(20, 0,5% покупателей)`; если
такого k нет, выбирается максимум без этого ограничения. Качество и размеры
кластеров для каждого k сохраняются в PostgreSQL.

Для выбранной модели публикуются принадлежности покупателей, центры в
стандартизованном и исходном масштабе, средние исходные признаки сегментов,
параметры импутации и масштабирования, а также координаты PCA для двумерной
визуализации. Сегментам не присваиваются заранее придуманные названия.

Результат является исследовательской сегментацией: k зависит от выбранных
признаков, масштабирования и метрики расстояния; силуэт на подвыборке может
отличаться от оценки на всей совокупности. Кластерные профили описывают данные и
не доказывают устойчивость поведения за пределами этого набора.
